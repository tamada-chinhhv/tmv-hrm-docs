# 勤怠端末（Hikvision）

**用途:** 物理的な勤怠端末（例: Hikvision DS-K1T342/343）を HRM に接続し、アプリ以外の打刻を勤怠表へ自動反映します。

**メニュー:** **システム設定** → **勤怠端末**

**権限:**

| 権限 | 内容 |
|------|------|
| **ATTENDANCE_DEVICE_VIEW** | 端末一覧・詳細・イベント・同期スケジュールの閲覧 |
| **ATTENDANCE_DEVICE_MANAGE** | 端末の追加/編集/削除、マッピング、接続確認、同期スケジュール保存 |

---

## 接続モード

| モード | 動作 | 選択目安 |
|--------|------|----------|
| **Direct** | HRM サーバーが LAN 上の端末 IP に ISAPI で接続しイベント取得 | 端末とサーバーが同一ネットワーク |
| **Push** | 打刻時に端末が HTTP リスニングでサーバーへ POST | サーバーから poll できない場合 |

**Push の注意:** 端末作成後に表示される **Host / URL / Port / Protocol** を端末の **HTTP リスニング** に貼り付けます。URL は **バックエンドポート**（多くは `:3001`）を指し、Web UI の `:3000` ではありません。

---

## 自動同期スケジュール

**勤怠端末** 画面上部の **自動同期スケジュール**:

| 項目 | 既定 | 意味 |
|------|------|------|
| **通常間隔** | 5 分 | 勤務時間外の取得間隔 |
| **勤務時間前後の間隔** | 1 分 | 出勤/退勤前後の取得間隔 |
| **勤務時間前後の幅** | ±30 分 | 短い間隔を適用する時間帯 |

出勤/退勤時刻は **システム設定** → **勤務時間** から取得（パネル内リンク）。

自動同期の対象:

- すべての **Direct** 端末。
- ISAPI 認証情報を保存した **Push** 端末（Push に加えて pull）。

ISAPI なしの Push 端末も HTTP リスニングで打刻を受信します。

---

## 端末の追加

1. **システム設定** → **勤怠端末** → **端末を追加**。
2. **Direct** または **Push**、名称・IP・支店（オフィス）を入力。
3. **Direct:** 必要なら ISAPI ユーザー/パスワード。
4. **Push:** 作成後に HTTP リスニング設定を端末へコピー。**トークンは一度だけ表示** — すぐ保存。

**期待結果:** 一覧に表示され、イベントまたは同期成功後 **Online** になります。

---

## 詳細ダイアログ

行の **表示** をクリック:

| タブ | 内容 |
|------|------|
| **概要** | 状態、同期、**Push 確認**（Push）、確認結果 |
| **設定** | 名称・場所・支店、ISAPI、ingest トークン再生成（Push） |
| **マッピング** | 端末ユーザー ID → HRM 従業員 |
| **イベント** | 打刻ログ（ページング） |
| **照合** | Direct のみ — 端末ユーザーとマッピングの比較 |

### Push 確認 / ヘルス

- **Push:** **Push 確認** — ingest URL、受信イベント、ISAPI pull（認証情報あり時）。
- **Direct:** 一覧のヘルスアイコン — ISAPI 接続テスト。

結果は行ごと（緑/黄/赤）に表示。必要時は URL をコピー可能。

---

## 従業員マッピング

打刻ごとに **端末ユーザー ID**（例: `251`）が送られます。

1. **自動:** **従業員コード** または HRM 従業員 ID と一致すれば、新規イベントでマッピング作成。
2. **手動:** **マッピング** タブで追加。

未マッピングのイベントは保存されますが、マッピング完了まで勤怠表には反映されません。

---

## 勤怠表への書き込み

本番書き込み有効時（`SHADOW_MODE=false`、書き込み ON）:

- その日 **最初** の打刻 → **出勤**。
- **最後** の打刻 → **退勤**。
- アプリ打刻と統合: **最早** 出勤、**最遅** 退勤。

端末のオフィス位置が勤怠オフィスとして使用されます（端末経路はアプリ geofence をバイパス）。

---

## トラブルシューティング

| 現象 | 対処 |
|------|------|
| Push: イベントなし | 端末の **HTTP リスニング**、サーバー IP + バックエンドポート、テスト打刻 |
| Host が `localhost` | IT が `PUBLIC_SITE_ORIGIN` を設定し、**トークン再生成** |
| ISAPI 401 | **設定** タブで認証情報を修正 |
| イベントはあるが勤怠なし | **マッピング**、shadow/本番書き込み設定を IT に確認 |
| ピーク時に同期を速く | **自動同期スケジュール** と **勤務時間** を調整 |

サーバー環境変数: [技術付録](../appendix/technical-reference.md)。
